# 表示言語（出力とダッシュボード画面）

2 つの言語は別物で、日本語の画面を英語の出力で使うこともある。設定の `locales`（掲載情報の言語）とも別。

- **出力の言語**（`i18n.rs`）: CLI の進捗・結果・エラー、差分、ヘルプが対象で、日本語・英語・簡体字中国語・繁体字中国語・韓国語・スペイン語・フランス語・ドイツ語・ブラジル・ポルトガル語の 9 言語。環境変数 `EDICTORA_LANGUAGE`（旧名 `EDICTORA_LANG` も読む。優先は前者）→ `LC_ALL` → `LC_MESSAGES` → `LANG`（空・C・POSIX は除く）→ OS の表示言語（`GetUserDefaultUILanguage`）の順に決め、判定できなければ英語。タグは `zh-Hans`/`zh-CN`/`zh-SG`→zh-CN、`zh-Hant`/`zh-TW`/`zh-HK`/`zh-MO`→zh-TW、`pt*`→pt-BR、それ以外は主言語で照合する。決定はプロセスで 1 回（初回の使用時）。引数・設定に頼らないのは、フックや引数の誤り（終了コード 2）より前でも決められるようにするため。
  - 文言は言語ごとの JSON 辞書（`locales/<タグ>.json`、`include_str!`）に持ち、コードは安定したキーで `tr!` / `trs!` 参照する（プレースホルダー `{name}`、辞書に無ければ英語、英語にも無ければキー）。整合テスト（`tests/localization.rs`）が全言語のキー集合・プレースホルダーの一致と、参照キーの存在・未使用キーの無さを固める。テストは `.cargo/config.toml` の `[env]` で `EDICTORA_LANGUAGE=ja` に固定する。
  - AI が読む文言（MCP のツール説明・スキーマ・応答）は英語に統一し、`edictora mcp` はプロセスの言語を英語に固定する。ログの定型文は作者が調べるためのものなので日本語のまま（ログに埋め込むエラー文は表示言語のまま）。ページ内スクリプトのエラーは固定の印を返し、Rust 側で各言語の文にする。README は英語を正本に 9 言語版を置く。
- **ダッシュボード画面の言語**（`dashboard/text.rs`）: `<html lang>` の主サブタグでページごとに 1 回だけ判定し、文言セット（JA / EN）を 1 つ選ぶ。要素ごとに「日本語か英語のどちらかに一致」で探さない（候補が倍になり取り違えの危険が増えるため）。lang が空なら日本語（確認済みの経路を lang 属性の有無で止めない。英語画面なら見つからずに止まる）。ja / en 以外は止める。
- **英語の文言は実画面で未確認**なので、安全側に倒す（「書いてよい」側へ推測で足さず、「止める」側だけに足す）。英語の成功メッセージの判定は単語単位・大文字小文字無視で、失敗を表す語（"not" など）を含むものは成功と見なさない。英語では送信前に送信完了メッセージが出ていないかを確かめ、出ていれば審査送信を始めない。"Unpublished" / "Not published" は "Published" の部分一致で許可されてしまうので書き込みを止める。
