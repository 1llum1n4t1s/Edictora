# 「プライバシー」タブ（Privacy practices）

- **対象**: ダッシュボードの「プライバシー」タブ（URL は `<編集画面>/privacy`。2026-11-18 に実画面で、画面の見出しは「単一用途」「権限が必要な理由」「データ使用」「プライバシー ポリシー」と確認した）。拡張機能に権限を足すと、このタブで権限の正当性などを入力しないと審査に送信できない。**設定の `privacy` に書いた欄だけ**を、掲載文と同じく正本ファイルから読み取り・比較・下書き保存する（書いていない欄は読み出し・比較・書き換えのどれにも使わない）。リモートコードの実欄は対象外。
- **設定の形**（`ItemConfig.privacy`、`config/privacy.rs`）: `singlePurpose`（本文の区間）・`permissions`（権限名 → 本文の区間。ホスト権限だけ特別なキー `host`。書いた順を保つ）・`remoteCode`（`uses`、true のときは `justification` が必須・false のときは書けない）・`dataUsage`（`collected`: 9 種類のうちチェックするもの、`certify`: **true だけを許す**。false・省略は設定エラー）・`policyUrl`。1 欄も無ければエラー（policyUrl も 1 欄に数える）。本文は説明文と同じ「ファイル + sectionStart / sectionEnd」で指し（`config/section.rs` を再利用）、固定書式を解析しない。取り出した本文は前後の空行を除き共通の字下げを取り除く（`privacy::dedent`）。空・1,000 文字（UTF-16、画面のカウンタ「n/1,000」）超過は、Chrome を開く前に終了コード 2 で止める。
- **欄の探し方**（`selectors::classify_privacy_textareas` など）: 単一用途と権限の正当性は textarea で、ラベルの行が「単一用途の説明」・「<権限名> が必要な理由」（ホスト権限は「ホスト権限 が必要な理由」→ キー `host`）。権限の欄は manifest の権限に応じて増減する（2026-11-18 の 15 アイテムでは 2〜7 欄で、ホスト権限の欄が無いアイテムもあった）。データの種類 9 つと宣誓 3 つは `input[type=checkbox]`（aria-label が項目の文言そのもの。value は種類が 1〜9、宣誓が "on"）で、1 行の完全一致で選ぶ。チェックボックスは不透明度 0 の 48x48 の input 自体が押される。クラス名には頼らず、文言は `text.rs` の `PrivacyText` に集める。**日本語の画面だけ**扱う（`PrivacyText` は日本語だけが持つ）。textarea の書き換えは掲載文と同じ（フォーカス → 全選択 → `Input.insertText` → 完全一致の確認）、チェックボックスは実マウス入力で押して状態の変化を待つ。
- **比較**: 文字列の完全一致（前後の空白も差分）。チェックボックスは設定キーを画面の並びで並べた文字列、宣誓は 3 つとも入っているかで比べる。**権限の一覧そのものも照合する**: `permissions` を書いたとき、設定にあって画面に無い権限、画面にあって設定に無い権限は、比較結果に「エラー」の行（理由つき）で出し、`diff` は終了コード 1、`push` は何も書かずに `WriteBlocked`（終了コード 4）で止める（欄の無い権限を黙って飛ばすと、正当性の入力漏れに気づけないため）。
- **手順**（`services::pull_privacy` / `diff_privacy` / `push_privacy`）: 画面操作は `PrivacyPage`（審査送信を持たない trait）だけを受け取る。push は「タブを開く → 書き込み可否 → 現在値を読んで比較 → 不整合があれば何も書かず止める → 差分のある欄だけ書き換え → 保存前に全欄を照合 → 書き込み可否 → 下書き保存 → 読み込み直して全欄を再照合」。どの段の失敗でも保存せず、失敗時のページのスナップショットを保存する。テキスト・画像の push とは別の保存として、その後に行う。書き込み可否の「主の入力欄」は単一用途の説明の textarea（`selectors::privacy_page_state`）、保存ボタンは編集画面と同じ「下書きとして保存する」。
- **プライバシー ポリシー URL**（`privacy.policyUrl`、`PrivacyField::PolicyUrl`、`PrivacyPage::write_policy_url`）: 2026-11-19 に実画面（SearchClock、日本語）で、`input[type=text]`（aria-label なし、`aria-labelledby` の参照先の文字列が「プライバシー ポリシーの URL」）、祖先に文字数カウンタ「39/2,048」（上限 2,048）、readOnly / disabled ではないことを確認した。設定は公式 URL などと同じ契約（キーなし＝対象外、`""`＝空欄が正本、それ以外は http(s) の絶対 URL だけ、2,048 文字以内。Chrome を開く前に終了コード 2）。モデルでは短い欄（`is_long_text()` が false）として 1 行比較・`- 現在値 / + 正本` の表示に乗る。画面は `selectors::find_policy_url_input`（ラベルの 1 行完全一致で 1 つに絞る。無ければ欄が無い扱い、複数なら止める）で選び、書き込みは `ensure_privacy_url_writable`（input だけ。textarea 用の `ensure_privacy_text_writable` は広げない）→ `rewrite_text`（空文字は Delete）。保存は「プライバシー」タブの保存に乗る。文言は `PrivacyText::policy_url_label`。
- **リモートコードは未対応**: 15 アイテムのどのタブにも欄が出ておらず DOM を確かめられなかったので、設定の形と比較の枠だけを持つ。画面側は常に「読めない」扱いで、設定に書くと `diff` がエラーを報告し `push` が止まる。実画面に欄が現れるアイテムで確かめてから対応する。
- CLI は `--only text|images|privacy`（既定はすべて。MCP の `only` も同じ）。`--locale` ではプライバシー タブを絞らない（全言語共通）。
