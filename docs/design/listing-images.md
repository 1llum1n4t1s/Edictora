# 掲載画像

- **対象**: ストア アイコン（128x128、1 枚。全言語共通。ダッシュボード上の名前は「ショップ アイコン」）・小タイル（440x280）・マーキー（1400x560）・全言語向けスクリーンショット（1280x800 か 640x400、1〜5 枚）・ローカライズ版スクリーンショット（言語ごと、同じ寸法・枚数）。プロモーション動画・並べ替えは対象外。v1 は PNG だけ（8 ビット・インターレースなし。アイコン以外は 24 ビット・アルファなし。**アイコンだけは透過（RGBA）も可**）。アイコンは全言語共通なので `--image-scope global` に含め、処理順は小タイルより前。
- **正本の検証**（Chrome を開く前、終了コード 2）: 実在・PNG ヘッダー・8 ビット RGB（アイコンは RGB か RGBA）・寸法・同一セット内で画素が重複しない・枚数。画素のダイジェストもここで計算する。
- **比較は画素で行い、比較不能を一致にも置換にもしない。** 2026-11-15 に SearchClock で、アップロードした PNG はサーバーが再エンコードして保存し（`=s0` の原本はバイト列もサイズも変わる。例: 901,028 → 1,052,742 バイト）、画素は完全に同じことを確かめた。そのためファイルの SHA-256 では比べず、`images/png.rs` でデコードした画素（行ごとにフィルターを戻した RGB）に幅・高さを前置した SHA-256 で比べる（zlib の展開は自前）。全不透明の RGBA は RGB に落として比べる。透過・インターレース・8 ビット以外は「比較不能」で、そのアイテムを止める（2026-11-15 のバックアップ 15 件・icon 除く 188 枚はすべて比べられた。181 枚が 8 ビット RGB、7 枚（DarkBlueThemeX 6・ScreenGuard 1）が全不透明の RGBA）。
  - **アイコンだけはアルファ込みのダイジェスト**（`png::pixel_digest_rgba`。幅・高さ・RGBA の画素列。完全に透明な画素は RGBA をすべて 0 に正規化して色を無視する。RGB は A=255 として扱う）で比べる。`images::digest_for_slot` が正本と原本の両方でスロットごとに選ぶ。アイコンは角丸などで透過画素を持つのが普通のため。
- **現在値の取得**: ページから段ごとの `<img>` の alt と src を集め、src の末尾のサイズ指定（`=w160-h100-rw` など）を `=s0`（原寸の原本）に置き換えて `net/winhttp.rs` で取得する（上限 16 MB、https の `*.googleusercontent.com` だけ、Cookie なし、リダイレクトなし）。Cookie なしで 200 が返ることを実画面で確認した。取得できなければ「比較不能」。
- **スロットの特定**（`selectors::pick_image_slot`）: 各 `input[type=file]` について「その入力だけを含む最大の祖先」の文字列を集め、寸法の表記（`128x128`・`1280x800`・`440×280`・`1400×560`）と見出しの行（「全言語向けアセット」「ローカライズ版アセット」）で 1 つに絞る。アイコンの入力は見出しの行を持たず（枠の文字列は「ショップ アイコン / 128x128 ピクセル / ガイドライン…」だけ）、`128x128` の表記とローカライズ版の見出しを持たないことで選ぶ。全言語向けとローカライズ版のスクリーンショットは同じ寸法なので、見出しで分ける。1 つに絞れなければ止める。言語が 1 つのアイテムにはローカライズ版のスロットが無い。
- **空のスロット**: 画像を削除したスロットには、alt だけを持つ src が空の `<img>` が残る。実画像だけ（src が空でないもの）を数える。
- **削除**: 画像の上へマウスを動かして削除ボタン（aria-label「画像を削除 <alt>」。アイコンの alt は「ショップ アイコン」）を出し、クリックする。確認ダイアログ「この画像を削除してもよろしいですか？この操作は元に戻せません。」（ボタン「キャンセル」「削除」）が出るので、文面を確かめて「削除」を押す。文面が違う・複数のダイアログなら押さずに止める。**画像まわりのクリックはこの 2 つ（aria-label が完全一致する削除ボタンと確認の「削除」）だけで、並べ替えには触れない。**
- **即時反映**: 削除は保存を待たずダッシュボードへ反映される。途中で止まると、下書きから画像が欠けたまま残りうる（再実行で整える）。
- **アップロード**: 1 枚ずつ `DOM.setFileInputFiles`。枚数が 1 枚増え、alt が「スクリーンショット N」の並びに揃い、エラー表示（結果メッセージに失敗を表す語）が無いことを待つ（1 枚 60 秒まで）。
- **push の順序**: テキストの push（対象なら）→ 編集画面を開く → 書き込み可否 → 全言語向け（アイコン → 小タイル → マーキー → スクリーンショット。差分のあるスロットだけ全入れ替え）→ 書き込み可否 → 下書き保存 → 読み直して照合 → ロケールごと（切替 → 置換 → 書き込み可否 → 保存 → 読み直し → 切替 → 照合）→ 保存したスロットがある場合は、最後に読み直して全対象スロットを再照合（何も保存していない場合は、最初の照合で読んだ画像から最終の照合結果を作り、画像の取得とロケールの切替を繰り返さない）。1 スロットの置換は「既存を末尾から 1 枚ずつ削除（毎回枚数が減るのを待つ）→ 正本を先頭から 1 枚ずつアップロード → 枚数を照合」。審査待ちなどでは最初の削除の前（`ensure_allowed`）と各保存の直前に止める。
- **ダッシュボードにあるロケールだけ**: ローカライズ版が対象で、そのロケールがダッシュボードに無い（言語が 1 つのアイテムを含む）なら、何も触らず全体を止めて `--image-scope global` か `--locale` を案内する。ローカライズ版を設定していないロケールは、現在 0 枚として扱う。
- **日本語の画面だけ**: 書き込みは日本語の画面だけ許す（英語の文言は未確認）。読み出しは、スロットを特定できれば英語でも動く可能性があるが、未確認。
- **ロケール切替の合図**: `switch_locale` は説明欄の値が 2 回続けて同じになるまで待つ。7 言語が同じ英語の説明を持つアイテム（Vuora）では切替前後で変わらず、切替前の画像を置換する恐れがあるため、ローカライズ版の書き込みは実画面で試す前に、画像の変化など別の合図を足す。
